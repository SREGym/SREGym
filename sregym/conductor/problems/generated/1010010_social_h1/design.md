# RPC lease identity migration

This incident evolves the previous distributed admission leak into a partial lease identity schema migration. A transport-level admission controller runs during nginx worker initialization. It writes compact SHA-1 reservation IDs to a Redis sorted-set occupancy index and a hash receipt journal, limiting each RPC upstream to 64 calls. A completion adapter installed during master initialization still uses the raw request ID. Redis reports successful commands with zero affected members, so completed calls silently strand capacity. This is a realistic incompatible client rollout: acquisition migrated to compact identifiers, while retirement retained its old wire format.

The receipt journal supports reconstruction of a lost occupancy index. Every admission transaction reconciles the index from unexpired receipts before checking capacity. Removing just the visible sorted sets therefore gives no sustained recovery. Reservations have a two-hour orphan timeout; continuous traffic replaces expired reservations, so the service does not heal over the required interval. User graph data is untouched.

The previous fixer inspected gateway errors, found a prominently named GenericObjectPool override in nginx.conf, and removed it. Here the image's GenericObjectPool remains unchanged, and acquisition belongs to TSocket in worker initialization. Removing the completion adapter leaves that independent admission stage active. Deployment rollback and ordinary restarts retain the effective ConfigMap and shared Redis state. Saturation is translated through the existing Thrift transport exception into connection timeouts naming healthy upstream services; the stack trace still exposes the worker-initialized open method, so the diagnosis is available rather than hidden.

An expert correlates near-zero backend demand with connection timeout failures at the gateway, notices init_worker_by_lua in the traceback, and reads both initialization stages. Compare Redis ZCARD and HLEN with actual in-flight calls, inspect ZRANGE/HKEYS identities, and trace redis.sha1hex(ARGV[1]) on acquisition versus session.reservation.id on completion. A repair can normalize IDs consistently and retire stale reservations, or remove both admission stages. The reference mitigation takes the latter route using only live ConfigMap and Redis state. It also retires both reservation key families after replacing frontend pods.

Injection alters only nginx.conf in the existing application ConfigMap and replaces nginx pods when its contents change. It does not change Deployment templates, images, service routing, observability, or data outside the admission namespace. Replay needs no saved configuration. Mitigation reconstructs the original configuration by removing the two introduced blocks; recovery performs the same operation. Scripts have no timing sleeps or helper resources and are idempotent. Validation results are stored alongside these artifacts.

## Validation

The original baseline reported zero violating rounds at approximately 102 requests/sec. Two initial two-minute SLO queries, completed 67.9 seconds apart, both reported 11/11 violating rounds and gateway error-log surges above 10,000 lines. Removing only the completion adapter, replacing the frontend pod, and deleting the occupancy indexes left HTTP timeline requests failing; the partial-mitigation query also reported 11/11 violating rounds.

Full mitigation ran twice successfully. Its SLO query reported all 3 available rounds healthy, zero errors, and 102.2–102.5 requests/sec. Recovery ran twice successfully and reported all 4 available rounds healthy. Both original ConfigMap data and Deployment spec were compared structurally with pre-change state and matched exactly. Those snapshots are used solely for validation; no script depends on them.

Replay ran inject.sh twice, with the second execution preserving the replacement pod. A subsequent live check deleted the home-timeline occupancy index while retaining its 64 receipt records, requested a timeline, and observed HTTP 500 plus a reconstructed 64-entry index. This demonstrates that index clearing is insufficient even after the acquisition code survives a pod replacement. Final replay SLO queries are recorded in replay-1.json and replay-2.json.

Final replay: both SLO queries reported 11/11 and 11/11 violating rounds, respectively, 84.5 seconds apart. The latter reported gateway error-log surges {'nginx-thrift': [0.0, 11520.0]}. The active frontend remained Running and Ready with zero restarts. The incident was left active for submission.
