The incident models a streaming codec adapter rollout in the OpenResty edge. Both changes are deployed as ordinary startup Lua in the existing nginx configuration, without changing images, Services, probes or the topology.

The outgoing framed transport subtracts four bytes from its payload length, assuming the buffer already owns the frame header. The original transport buffer contains only the payload; flush adds the header separately. This produces a shorter advertised frame, with trailing bytes interpreted as the next frame header. Backend handlers report oversized frames and the frontend reports generic transport exceptions.

The same rollout adds a string reader intended to honor an eight-KiB streaming segment budget. It instead reads at most eight bytes of a length-prefixed string and returns immediately, without consuming the rest. RPC method names already exceed that size, so even successful backend responses become malformed. Repairing the request encoder alone therefore does not restore service; repairing only the decoder preserves invalid outgoing frames. A global budget increase cannot fix the independent frame accounting error.

An expert would correlate simultaneous failures across independent backend RPCs, inspect the client framing boundary, and compare runtime startup overrides with the shipped transport implementation. After fixing request framing, the changed error signature localizes the remaining response parser problem. Removing both overrides restores the original library contracts. No application data repair is needed.

The live nginx ConfigMap survives restarts and Deployment rollback. All application pods remain Ready. Telemetry retains actual application errors; no monitoring objects are modified. The supplied mitigation reads only current cluster state. Recovery uses the pre-change ConfigMap data saved by the injector and restores it exactly. Injection is deterministic and leaves no helper resources. Validation records are saved separately under validation/.

Live validation: both changes together violated every measured round and increased frontend error logs from zero to thousands per two-minute window. Correcting only frame lengths left approximately 90% errors in steady rounds; correcting only the string decoder left 100% errors. Full mitigation restored zero-error healthy rounds, and ConfigMap data matched the saved healthy data byte for byte. Injection and mitigation were each exercised twice. Detailed endpoint responses document the measurement windows.

Exact recovery and its repeated invocation also returned a wholly healthy SLO window. Final replay, repeated injection, and an additional frontend pod replacement retained the incident; two subsequent checks separated by at least sixty seconds showed every round violated with all pods Running and Ready.
